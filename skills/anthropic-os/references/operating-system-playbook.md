# Operating System Playbook

Load this reference for diagnostics, practice selection, or copy-ready experiment artifacts.

## Layer Model

| Layer | Purpose | Evidence |
|---|---|---|
| L0 boundary | State what analogy/model may and may not prove | Assumptions and counterexamples |
| L1 livewired | Adapt practices under competition and constraint | Observed feedback and resource limits |
| L2 3B | Bend, break, or blend candidate mechanisms | Alternatives and falsifiers |
| L3 flywheel | Reinforce one recurring value loop | Input/output/feedback metrics |
| L4 predictive | Learn from predicted versus actual outcomes | Calibration ledger |
| E0 evolution | Review practice versions under governance | Promotion/retirement receipt |

Brain/computer analogies are design prompts, not scientific equivalence claims.

## Maturity Evidence

Score 1-5 only from local observations:

1. Data and experiment maturity.
2. AI-native development/work execution.
3. Decision latency and reversibility.
4. Cultural transparency and dissent safety.
5. Strategic focus and allocation discipline.
6. Tool flywheel, maintainability, and operator control.

Each score needs an example, counterexample, confidence, and next probe. Do not use code-generation percentage or extreme productivity as a universal target.

## Candidate Flywheels

- Growth: hypothesis -> test -> behavior evidence -> next hypothesis.
- Engineering: specification -> implementation -> eval -> reusable tooling.
- Culture: proposal -> independent views -> decision -> retrospective.
- R&D: exploration -> measured result -> knowledge -> next experiment.
- Strategy: future state -> allocation -> milestone -> reallocation.
- Personal effectiveness: goal -> minimum behavior -> evidence -> review.
- Human-AI symbiosis: intent -> agent action -> human correction -> eval update.

Choose one. Multiple simultaneous flywheel redesigns hide causality.

## CASH Boundary

This repository retains “CASH” as a local name for a structured hypothesis-to-feedback experiment loop. Its acronym expansion is not established in the source skill; ask for the local definition rather than inventing one. Minimum contract:

```text
Claim/hypothesis:
Audience/cohort:
Smallest test:
Metric and predicted effect:
Guardrails:
Budget and duration:
Stop/rollback:
Observed result:
Learning and next decision:
```

## Prediction Ledger

| decision | human prediction | agent prediction | actual | error | evidence | weight change | review |
|---|---|---|---|---|---|---|---|

Do not change trust weights from one anecdote. Seek repeated, comparable predictions and guard against correlated errors.

## Success-Disaster Check

- What breaks if demand, output, or adoption is 10x forecast?
- Which quality/safety/privacy metric degrades first?
- Who receives alerts and has stop authority?
- What can roll back immediately; what needs compensation?
- Can the owner still explain the system at scale?

## Evolution Decision

At review choose `keep`, `adapt`, `retire`, `combine`, or `continue-testing`. Record metric delta, guardrails, feedback quality, scope, owner, and rollback. Retirement archives accessibly; it never deletes history or rewrites evidence.
